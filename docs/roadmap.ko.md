# MVP에서 실제 운영까지

현재 제공되는 기능: 수동 API 수집, CSV 입력, 규칙·군집 분석, 과거 결과 통계, 비용을 반영한 전략 내역, 옵션 손익 시뮬레이션, 한국어·영어 화면.

실제 데이터를 수동으로 분석하는 도구로는 사용할 수 있습니다. 지속적으로 최신 상태를 제공하는 서비스와 신뢰할 수 있는 전략 연구 결과를 완성하려면 아래 작업이 필요합니다. 자동매매는 별도 범위입니다.

| 순서 | 필요한 작업 | 필요한 결정·자료 | 완료 기준 |
| --- | --- | --- | --- |
| 1 | 데이터 운영 자동화 | 기준 거래소, 갱신 주기, 실행 서버 | 증분 수집·중복 방지·원본 보존·누락 재수집이 작동하고 실패/오래된 데이터가 화면과 로그에 표시됨 |
| 2 | 충분한 과거 데이터 확보 | OI 이력, 일관된 단위, 데이터 예산 및 이용 권한 | 연구 기간 전체의 범위·결측률·공개 시각·수정 정책을 문서화함 |
| 3 | 온체인 연동 | MVRV/SOPR/순유입 제공처 또는 검증한 쿼리, 이용 권한과 API 인증 | 공개 시각 기준 결합 및 지표별 테스트 완료. 데이터가 없으면 기능을 비활성화하며 대체값을 만들지 않음 |
| 4 | 모델 검증 확장 | 사전 고정 가설, 새로운 미사용 평가 기간, 기준 전략 | 가격만 / 가격+파생 / 온체인 추가 모델을 동일 날짜에서 비교하고 실패한 실험도 기록함 |
| 5 | 운영 배포 | 호스팅 계정, 공개/비공개 여부, 저장소 연결, 비용 한도 | HTTPS 접속, 재시작 후 데이터 유지, 비밀정보 관리, 오류 로그·상태 확인·백업·복구 시험 완료 |
| 6 | 역사적 옵션 백테스트 | 실제 과거 옵션 호가·만기·행사가·정산 규칙·거래비용 | 당시 존재한 계약만 선택하고 실제 체결 가능 가격 및 담보 조건으로 손익을 재현함 |

## 가장 먼저 할 일

첫 개발 단위는 **자동 데이터 갱신과 품질 상태 표시**입니다. 후보 기준은 BTCUSDT, 단일 거래소, UTC 일봉입니다. 현재 검증에서는 Bybit의 요청 구간에 OI가 존재했지만, 향후 제공 범위가 동일하다고 보장하지는 않습니다. 수집 시 매번 범위를 검사해야 합니다.

스케줄러가 원본과 정규화된 스냅샷을 저장하고 대시보드는 마지막 정상 스냅샷을 읽도록 분리합니다. API 장애를 숨기지 말고 마지막 성공 시각과 누락된 필드를 보여줍니다. 예정된 갱신이 실패했을 때 복구·재시도와 알림을 검증합니다.

그다음 동일 데이터 범위에서 가격-only, 기본 모델, OI 추가 모델의 비교 리포트를 만듭니다. 온체인 예산을 쓰기 전 파생상품만으로 추가 정보가 있는지 먼저 확인할 수 있습니다.

## 사용자가 정해야 할 사항

1. **목적:** 개인 리서치/포트폴리오 데모인지, 다른 사용자가 접속하는 서비스인지.
2. **공개 범위:** 공개 데모인지, 인증이 필요한 비공개 서비스인지.
3. **데이터 예산:** 무료 파생상품 데이터로 먼저 진행할지, 온체인·옵션 이력에 비용을 배정할지.
4. **운영 환경:** 개인 PC 실행을 유지할지, 상시 서버에 배포할지.

API 비밀키는 채팅이나 GitHub 파일에 넣지 않고 배포 환경의 비밀정보 저장소에 등록합니다. 데이터 가격과 API 이용 조건은 계약 시 제공처에서 다시 확인해야 합니다.

## 완료의 정의

“전체 기능이 작동한다”는 것은 데이터를 자동으로 갱신하고, 문제를 감지하고, 과거 정보만으로 분석을 재현하며, 사용자가 결과의 한계를 확인할 수 있고, 서버가 재시작되어도 복구되는 상태입니다. 수익성이 검증되었다는 의미는 별도의 새 데이터 검증을 통해 판단합니다. 옵션 이력이 없으면 옵션 페이지는 계속 시뮬레이터로 표시해야 합니다.
