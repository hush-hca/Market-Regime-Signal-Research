# Frozen forward observations

Protocol `frozen-kmeans-v1` registers each venue and fixed feature set at its first eligible real collection. Four standardized KMeans centroids and scaler mean/scale are saved numerically (no pickle), along with training snapshot, train end, row count, features, labels, registration timestamp and feature-definition SHA-256. Labels rank centroid 30-day momentum. Minimum training rows: 180; seed: 42; n_init: 10. These are fixed research parameters, not observed market values.

The collector never refits an existing artifact. Changed feature code is rejected. Each latest market date is recorded at most once per model, for horizons 7/14/30. Missing inputs create a missing_inputs record without a prediction or scheduled entry. Older dates are never replayed as forward predictions. Registration is persistent in forward_models, and decisions/outcomes in forward_ledger, each using the immutable store. Registry publication precedes ledger publication; single workflow concurrency prevents competing writers.

A ready record schedules entry at the first UTC midnight strictly after actual recording time. Positive observed 30-day momentum gives a paper Long; otherwise Abstain. Each later collector reads actual completed daily bars for that same venue. It stores the observed entry open with its version, then the expiry-day open and version. Asset gross return = exit open / entry open - 1. Paper gross return equals that change only for Long and remains absent for Abstain; no assumed cash interest or net costs. Funding, fees, slippage and interest are excluded. Daily signals and different horizons overlap: do not infer independent-sample significance from their count.

Already recorded model labels, feature values, entry prices and completed outcomes remain unchanged when later source revisions arrive. A separate corrected research analysis may be published explicitly; it must not rewrite the forward record. A long outage can resolve outcomes later but cannot invent missing daily decisions. Incomplete/missing bars remain pending. Market freshness gate: 36 hours after last daily close. GitHub timing is best-effort, and real elapsed time is required before outcomes exist.

On-chain features use real current-vintage observations available to the collector; historical training alignment applies the disclosed 48-hour policy. This does not reconstruct past first-publication vintages. Market and on-chain source versions are retained. Frozen forward models and historical walk-forward fits are different models and must not be conflated.

This is a paper research ledger, not exchange orders, executable net performance or a calibrated probability forecast. No fabricated entries, prices, costs or outcomes are inserted for display.

Recovery safety: missing pointers in established forward directories, corrupt latest versions and pointers older than immutable versions stop collection rather than reset history. Registry/ledger model IDs must agree. New signal dates must increase for each model; older source snapshots cannot create retrospective predictions. Operator recovery must preserve all published records. Feature fingerprints include referenced column-list constants as well as implementation source.
